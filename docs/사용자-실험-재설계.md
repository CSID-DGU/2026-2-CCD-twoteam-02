# 사용자 실험 재설계 (작성 중)

집중을 **트래킹으로 판정하지 않고, 선행연구의 측정 방식으로** 재도록 사용자 실험을 다시 짜는 문서다.
계속 고쳐 나가며, 정리되면 팀 검토를 받는다.

- 담당: 최원준. 시작: 2026-10-14
- 출처 표시: **[원문]** 원문 직접 확인 / **[공식]** 공식 문서 / **[2차]** 요약·재인용 자료

---

## 0. 왜 다시 짜는가

- 발표 피드백(2026-10-14): 트래킹은 집중을 평가하는 요소이므로 제대로 구현해야 하고, 학습기기 모드처럼 "일괄 인정/불인정"으로 처리하면 안 된다.
- 기존 제안서는 **초록불(트래킹 판정) 시간 비율**을 집중의 객관 지표로 썼다. 트래킹이 현실감을 만드는 장치이면서 동시에 집중을 재는 자가 되면, **우리 도구의 효과를 우리 도구로 재는 셈**이다.
- 그래서 역할을 나눈다.
  - **집중 측정**: 선행연구에서 검증된 방식 (수행 성과, 경험 표집, 검증된 설문)
  - **트래킹**: 실제 스터디카페처럼 함께 있는 느낌(현실감)을 만드는 장치. 집중의 증거로 쓰지 않는다.
- 연구 질문: **다른 사람의 트래킹 캐릭터가 보이면(C), 안 보일 때(B)보다 더 집중하는가?**

## 1. 기존 계획에서 뺀 것과 이유

| 뺀 것 | 이유 |
|---|---|
| 초록불 시간 비율로 집중 비교 | 우리 도구로 우리 도구를 재는 구조. 판정에 일괄 규칙(숙이면 공부로 인정 등)이 섞여 있음 |
| 노란불 전체 비율·졸음·고개 숙임 판정 | 판정 규칙이 아직 세밀하지 않음. 공부 자세를 사람별로 판정할 수 있게 되면 다시 검토 |
| 직접 만든 7점 문항 ("공부에 집중할 수 있었다" 등) | 검증되지 않은 문항이라 측정 정확도를 주장할 수 없음 → 검증된 척도로 교체 |
| A 조건 (Zoom 캠 ON) | 프로그램·화면·측정 방법이 모두 달라서, 차이가 나도 원인이 "함께 있어서"인지 "Zoom이라서"인지 구분 불가. 노출 부담(H1)은 집중 측정과 별개 |
| "성과가 같거나 높다"의 "같다" 주장 | 24명으로 "차이 없음"을 증명할 수 없음. "높다"만 검증 |
| SUS(사용성)·선호도 | 집중 측정과 무관. 필요하면 실험 후 따로 받음 |
| 전자기기 감지 (실험에서만) | 아래 4절 |

**보조 지표로 남긴 것**
- **다른 화면 전환**: 영상 인식이 아니라 브라우저가 알려 주는 값(`document.hidden`, `hasFocus`)이라 정확하다.
- **자리 이탈**: 얼굴이 사라지는 큰 사건이라 비교적 정확하다고 봤지만, **재검토 중** (7절 — 배포 사이트에서 누워 있던 시간이 공부 시간으로 들어간 사례).

## 2. 새 실험의 뼈대 (초안)

- **조건**: B(캐릭터 숨김 모드) vs C(본 서비스). 둘 다 우리 앱을 쓰고 **다른 사람 캐릭터가 보이는지만** 다르다.
- **설계**: 24명이 두 조건을 모두 수행(참가자 내 설계). 절반은 B→C, 절반은 C→B (순서 효과 상쇄).
- **과제**: 연속 계산(크레펠린 방식) 30분. 조건마다 다른 무작위 숫자 세트.
- **진행 (약 90분)**: 안내 10분 → 조건 1 30분 → 설문·휴식 10분 → 조건 2 30분 → 설문 10분
- **통제**: 휴대폰은 다른 방, 학습기기 미사용.

### 측정
| 구분 | 지표 | 근거 |
|---|---|---|
| 객관 (주) | 분당 작업량, 정답률, 전반 15분 대 후반 15분 차이, 반응 시간 변동성 | 크레펠린 작업 곡선, 컴퓨터판 크레펠린(CKT) 연구 |
| 공부 중 | 경험 표집 3회: "방금 문제 풀이에 얼마나 몰입했나요?" 0~5 | Mark 외 CHI 2014 [원문] |
| 공부 후 | 성인용 학습몰입 척도의 "집중" 하위요인, Paas 정신 노력 1문항 | 국내 타당화(대학생·대학원생 476명), 학습 연구 표준 |
| 조작 확인 | 사회적 실재감(Networked Minds) 공존감 문항 | C에서 실제로 "함께 있다"고 느꼈는지 확인 |
| 보조 | 다른 화면 전환, (재검토 중) 자리 이탈 | 1절 |

## 3. 세션 30분의 근거

- **경계 저하 (Teichner 1974)**: 집중을 유지하는 과제에서 수행 저하는 시작 후 **20~35분이면 끝나고, 그 절반 이상이 첫 15분 안에** 일어난다. [2차 — National Academies 재인용]
  - 30분이면 저하 과정을 처음부터 끝까지 담는다. 20분은 끝나기 전에 잘릴 수 있다.
- **우치다-크레펠린 표준 절차**: 15분 계산 → 5분 휴식 → 15분 계산 (총 30분 작업), 1분마다 줄 바꿈. [2차]
- **경험 표집 간격 (Mark 2014)**: 15분마다 물었다 → 30분에 2~3회가 자연스럽다. [원문]
- 결정: 조건마다 **30분 연속**(중간 휴식 없음, 저하가 끊기지 않게), 분석은 전반·후반 15분으로 나눈다.

## 4. 전자기기 감지를 실험에서 뺀 이유

1. **부정확한 측정은 효과를 가린다.** 조건과 무관하게 무작위로 생기는 측정 오류(비차별적 오분류)는 진짜 차이를 0 쪽으로 약하게 만들고 검정력을 떨어뜨린다. 우연히 나온 유의한 결과가 거짓 양성일 가능성도 커진다. [2차 — 역학·측정 연구] 전자기기 감지는 정확도가 아직 검증되지 않았다.
2. **통제가 측정보다 먼저다.** 실험 설계의 기본은 결과에 영향을 줄 수 있는 변수를 모든 조건에서 똑같이 고정하는 것이다. 휴대폰을 다른 방에 두면 그 요인이 아예 사라진다.
3. **휴대폰은 놓인 위치만으로도 영향을 줄 수 있다.** Ward 외(2017)는 책상 위 휴대폰만으로 인지 수행이 떨어진다고 보고했지만, 2022년 사전등록 재현 연구에서는 재현되지 않았다. 효과가 있든 없든 모든 조건에서 "다른 방"으로 같게 두면 안전하다.
4. **서비스 기능으로는 유지한다.** 정확도는 실험과 분리해 각본 시험(정해진 횟수만큼 휴대폰을 들고 감지율 확인)으로 따로 검증한다.

## 5. 과제를 연속 계산(크레펠린 방식)으로 고른 이유

**방식**: 한 자리 숫자가 줄지어 있고, 이웃한 두 수를 더한 값의 일의 자리를 적는다. 1분마다 다음 줄로 넘어간다. 분당 작업량·오류·작업 곡선을 본다. 일본에서는 우치다-크레펠린 검사로, 독일·인도네시아에서는 비슷한 Pauli 검사로 쓰인다. 컴퓨터판(CKT)은 정신 피로 연구에서 반응 시간·반응 시간 변동성·정답률을 기록하는 데 쓰였다. [2차]

**우리 실험에 맞는 이유**
1. **세트 난이도가 같다는 것을 보장할 수 있다.** 숫자를 무작위로 뽑으면 세트끼리 난이도가 구조적으로 같다. 독해 문제처럼 난이도를 맞추는 예비 실험이 필요 없다.
2. **30분 안에 다 풀 수 없다.** 끝까지 측정이 이어진다.
3. **채점이 자동이고 객관적이다.**
4. **분 단위 작업 곡선**으로 집중이 떨어지는 과정을 볼 수 있다.
5. **가설 방향과 이론이 맞는다.** 사회적 촉진 이론(Zajonc)에 따르면 단순하고 익숙한 과제는 남이 있을 때 수행이 좋아진다. 반대로 새롭고 어려운 과제는 남(사람이 조종한다고 믿은 아바타 포함)이 있을 때 수행이 떨어질 수 있다(Hoyt·Blascovich·Swinth 2003). 단순 계산은 이 위험을 피한다.

**약점 (한계로 적을 것)**
- 집중력 측정 도구로서의 타당도 근거는 약하다. 주로 적성·성격 연구이고, 인도네시아 심리학자 델파이 조사에서도 근거 기반이 탄탄하지 않다는 결론이 나왔다. [2차] → 집중을 직접 재는 도구가 아니라 **객관적인 작업 수행 지표**로 쓰고, 집중은 경험 표집과 검증된 설문으로 함께 잰다.
- 실제 공부와는 거리가 있다. 단순 계산에서의 효과가 실제 공부에도 그대로 나타난다고 말할 수 없다.
- 보완 방향: 공부 상황에서 집중을 잰 선행 실험의 방식을 그대로 가져올 수 있는지 조사 중 (7절).

## 6. 꼭 할 것

1. **과제 화면** (새 기능): 앱 안에서 할지, 종이로 할지 결정 필요 (7절)
2. **경험 표집 팝업 + 응답 저장** (새 기능)
3. **숙여서 공부할 때 졸음으로 잡히는 문제 수정**: 다른 참여자에게 틀린 노란불이 보이면 현실감을 해친다.
4. **캐릭터 반영 품질**: C 조건의 "함께 있는 느낌"이 여기서 나온다.
5. **카메라 가이드라인 착석 확인 + 버그 #80**

미루는 것: 전자기기 감지(서비스 기능, 실험 후), 졸음 EAR 재설계(3번 수정 후 판단)

## 7. 열린 문제

- **자리 이탈을 보조 지표로 쓸 수 있는가**: 배포 사이트를 켜 두고 누워 있다 왔는데 공부 시간으로 반영됨(2026-10-14). 원인 확인 필요 (얼굴이 화면에 잡혔는지, 배포본의 기준값 등).
- **과제를 앱 안에 넣으면 "카페에서 함께 공부하는 느낌"이 사라지지 않는가**: 화면 가운데를 과제가 차지하면 다른 사람 캐릭터가 덜 보인다. 종이 과제 또는 3D 화면을 남긴 배치를 검토.
- **공부 상황 집중 측정 선행 실험의 방식을 그대로 채택할 수 있는가**: 조사 중.
