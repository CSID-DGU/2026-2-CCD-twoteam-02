# 각본 시험 (트래킹 판정 정확도 기술 평가) 설계

- 작성: 최원준, 2026-10-15
- 관련: `docs/사용자-실험-재설계.md` 5-1절(평가 두 갈래), 8절 8번(각본 시험표), Issue #119·#120·#80
- 순서: 카메라 가이드라인 개편(#80, Pose 하나로 합치기 포함)을 먼저 끝낸 뒤 이 시험을 구현한다. 가이드라인 없는 판정(기준 결과)은 개편과 무관하므로 "고치기 전 측정"은 그대로 유효하다.

## 1. 목적

트래킹 판정(초록·노랑)과 공부 시간 기록이 웹 서비스 기능으로 쓸 만큼 정확한지 **정답을 미리 정해 둔 행동**으로 잰다.
순서: 지금 정확도 재기 → 고치기 → 다시 재기. 고친 효과를 숫자로 보이려면 고치기 전에 먼저 잰다.

- 실제 사용 중에는 정답(그때 정말 공부했는지)을 모르므로 정확도 수치를 낼 수 없다. 실제 사용의 오판 신고(#121)는 각본에 없던 오판을 찾는 용도로만 쓴다.
- 제안서 성공지표와 대응: 판정 정확도 80% 이상, 필기 중 오판율 10% 이하, 공부 시간 기록 오차 ±10% 이내.

## 2. 두 가지 판: 빠른 점검판과 정식판

| | 빠른 점검판 | 정식판 |
|---|---|---|
| 용도 | 어디서 틀리는지 찾기 | 제안서 지표 보고 |
| 반복 | 행동마다 1회, 목록 순서대로 | 행동마다 5회, 순서 섞기 |
| 사람 | 최원준 | 최원준·김현·육심호 (안경·조명·얼굴형이 다르도록) |
| 시간 | 약 10분 | 1인 약 50분, 2~3번에 나눠서 |
| 시점 | 지금 (고치기 전) | 고친 뒤 |

빠른 점검판에서 틀린 행동은 그 행동만 2~3번 더 해서 원인을 확인한다. 빠른 점검판 결과는 정확도 수치로 쓰지 않는다.

## 3. 행동 표

기준값은 `focusLogic.ts` 기준: 자리 이탈 60초, 졸음 21초(정면만), 다른 화면 즉시. 마감 = 기준 + 여유 5초(다른 화면은 2초).
아래 길이는 빠른 점검판 기준이며, 정식판도 같은 길이를 쓴다.

### 정답 = 초록 유지 (노란불이 한 번이라도 뜨면 오답)

| # | 행동 | 길이 | 공부로 들어가야 할 시간 | 비고 |
|---|---|---|---|---|
| 1 | 정면 공부 (화면 읽기·타자) | 60초 | 60초 | |
| 2 | 숙여서 종이 읽기 | 60초 | 60초 | #119, 필기 오판율 |
| 3 | 숙여서 필기 | 60초 | 60초 | 필기 오판율 |
| 4 | 턱 괴기·자세 바꾸기 | 60초 | 60초 | |
| 5 | 잠깐 고개 돌리기·물 마시기 (10초 정도) | 60초 | 60초 | |
| 6 | 잠깐 자리 비우기 (처음 30초 비우고 돌아와 앉기) | 60초 | 60초 | 보류 규칙: 기준 안에 돌아오면 비운 시간도 인정 |

### 정답 = 노란불 (마감 안에 기대한 상태가 떠야 정답, 다른 종류의 노란불이면 오답)

| # | 행동 | 길이 | 기대 상태 | 마감 | 공부로 들어가야 할 시간 |
|---|---|---|---|---|---|
| 7 | 자리 비우기 (카메라 밖으로 — 침대에 눕기 등 포함) | 90초 | 자리 이탈 `away` | 65초 | 0초 |
| 8 | 정면을 보고 눈 감고 있기 | 30초 | 졸음 `drowsy` | 26초 | 0초 |
| 9 | 다른 탭 열기 | 30초 | 다른 화면 `offscreen` | 2초 | 0초 |
| 10 | 다른 앱 누르기 | 30초 | 다른 화면 `offscreen` | 2초 | 0초 |

- 7번은 #120 재현도 겸한다. 카메라 밖 침대에 누운 것도 "카메라 밖으로 나감"이라 자리 비우기와 같은 행동이다. #120에서는 그런데도 초록이 유지됐으므로 트래킹 버그로 보고, 원인 확인을 위해 얼굴 인식 여부 등을 함께 기록한다(5절).
- 노란불 행동의 "공부로 들어가야 할 시간 0초"는 근사다. 노란불이 되기 전 보류 시간은 버려지므로 0에 가까워야 한다.

### 이번에 넣지 않는 것 (시험 후 할 수 있는 부분부터 추가)

- 숙인 채 졸기: 지금 규칙은 숙이면 졸음 판정을 하지 않으므로 항상 오답이 된다. 한계로 둔다.
- 전자기기 감지: 실험과 같은 이유로 제외(아직 구현 전).
- 가이드라인 이탈 행동: 기준값이 임시(5초)라 개편 때 추가. 다만 가이드라인을 켠 판정은 6절처럼 함께 채점한다.
- 학습기기 사용함 모드: 실험은 기본 모드(사용 안 함)이므로 이번엔 재지 않는다.

행동은 `scriptTest.ts`의 행동 표 한 곳에만 있으므로, 추가할 때는 표에 한 줄만 넣으면 된다.

## 4. 진행 방식

1. `/tracking` 화면의 "각본 시험" 패널에서 빠른 점검판 / 정식판을 고르고 시작한다.
2. 패널에 다음 행동 이름이 보인다. **스페이스바**를 누르면 그 행동이 시작되고, 행동 이름과 남은 시간이 크게 보인다.
3. 정해진 시간이 지나면 **삐 소리**가 나고 그 행동이 자동으로 끝난다. (눈 감기·자리 비우기 중엔 화면을 못 보므로 소리로 알림)
4. 행동 사이는 쉬는 시간이며 채점하지 않는다. 준비되면 다시 스페이스바.
5. 모든 행동이 끝나면 결과표가 화면에 바로 뜬다. CSV 내려받기 버튼은 기록 보관용이다.

- 다른 탭(9번)으로 가 있는 동안 브라우저가 타이머를 늦출 수 있다(최대 1초 이상 간격). 기록 간격이 벌어져도 채점은 시각 기준이라 문제없다.
- 6번처럼 행동 안에서 움직임이 바뀌는 경우는 패널에 행동 설명을 함께 보여 준다.

## 5. 기록하는 값

0.1초마다 한 줄. 영상·이미지는 기록하지 않는다. 내 컴퓨터로 내려받기만 하고 서버로 보내지 않는다.

| 열 | 내용 |
|---|---|
| `t` | 시험 시작 후 경과(ms) |
| `trial` | 행동 순번 (쉬는 중이면 빈칸) |
| `behavior` | 행동 번호 |
| `elapsed` | 행동 시작 후 경과(ms) |
| `status` | 판정 상태 — 가이드라인 없이 (지금 공부 화면과 같음) |
| `studyMs` | 집중 시간 — 가이드라인 없이 |
| `statusGuide` | 판정 상태 — 가이드라인 켬 |
| `studyMsGuide` | 집중 시간 — 가이드라인 켬 |
| `found` | 얼굴 인식 여부 |
| `blink` | 눈 감김 점수 |
| `pitch` | 고개 위아래 각도(라디안) |
| `framed` | 머리~가슴이 화면 안인지 (가이드라인 Pose 결과, 모르면 빈칸) |
| `hidden` | 탭 숨김 여부 |
| `focused` | 창 선택 여부 |

## 6. 채점

판정을 두 가지로 동시에 계산해 각각 채점한다.
- **가이드라인 없이**: `useFocusState(face, false)` — 지금 실제 공부 화면(`StudyRunner`)과 같은 방식. 이것이 기준 결과다.
- **가이드라인 켬**: `useFocusState(face, false, guide)` — 가이드라인을 공부 시간 측정에도 쓰면 정확도가 오르는지 보기 위한 비교.

행동 하나의 채점:
- 초록 행동: 행동 시간 동안 상태가 한 번이라도 `focus`가 아니면 오답.
- 노란불 행동: 행동 시작 후 마감 안에 기대 상태가 처음 나타나면 정답. 다른 노란불만 나오거나 마감을 넘기면 오답. 정답일 때 걸린 시간도 기록.
- 시간: 행동 시작·끝 시점의 `studyMs` 차이 = 실제로 들어간 시간. 공부로 들어가야 할 시간과 비교.

결과표:
- 행동별: 정답/오답(정식판은 맞은 횟수/전체), 노란불까지 걸린 시간, 들어간 시간 vs 들어가야 할 시간 — 가이드라인 없이 / 켬 두 칸.
- 요약: 전체 정확도, 필기 오판율(2·3번에서 노란불이 뜬 비율), 공부 시간 오차 = (들어간 시간 합 − 들어가야 할 시간 합) ÷ 들어가야 할 시간 합.

가이드라인 결과를 실제 공부 화면에 쓸지(카메라 이상 시 팝업 포함)는 이 비교 결과를 보고 가이드라인 개편(#80) 때 정한다. 도움이 안 되면 쓰지 않는다.

## 7. 파일 구성

| 파일 | 역할 |
|---|---|
| `src/focus/scriptTest.ts` | 순수 로직(React 무관). 행동 표, 순서 만들기(빠른: 표 순서 / 정식: 5회 섞기), 채점, CSV 만들기. Node로 시나리오 검사 |
| `src/focus/ScriptTestPanel.tsx` | 패널 화면: 판 고르기, 스페이스바, 남은 시간, 삐 소리(Web Audio, 라이브러리 없음), 0.1초 기록, 결과표, CSV 내려받기. 판정 두 가지를 `useFocusState`로 직접 계산 |
| `src/HeadTrackingTest.tsx` (김현 파일) | 패널을 불러오는 줄만 추가 (`face`, `guide`를 넘김) |

- 새 의존성 없음.
- 기록은 메모리에만 쌓는다(10분 ≈ 6,000줄, 정식판 50분 ≈ 30,000줄 — 수 MB 이하). 새로고침하면 사라지므로 끝나면 바로 내려받는다.
- Pose는 가이드라인 개편에서 하나로 합친다(한 번 인식해서 가이드라인·팔이 각자 필요한 값을 가져감). 이 패널은 합쳐진 결과의 가이드라인 값만 받는다.

## 8. 검증

- `scriptTest.ts`: Node로 채점 시나리오 검사 (초록 유지 정답, 중간 노란불 오답, 마감 안 이탈 정답, 마감 넘김 오답, 다른 종류 노란불 오답, 시간 오차 계산).
- `npm run lint`, `npm run build`.
- 화면 동작(스페이스바, 소리, 결과표, CSV)은 개발 서버에서 사용자가 확인.

## 9. 한계

- 빠른 점검판은 1회씩이라 문제 찾기용이고 정확도 수치가 아니다. 정식판도 5회라 한 번 틀리면 20%씩 움직인다.
- 시험하는 사람이 정해진 동작을 정확히 했는지는 본인을 믿는다.
- 각본에 있는 행동만 잰다. 실제 공부의 다양한 행동은 현장 연구의 오판 신고로 보완한다.
