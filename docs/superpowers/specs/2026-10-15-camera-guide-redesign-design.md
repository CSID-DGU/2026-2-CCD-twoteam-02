# 카메라 가이드라인 개편 설계

- 작성: 최원준, 2026-10-15
- 이전 설계: `2026-10-09-camera-guide-design.md` (이 문서가 대체)
- 관련: Issue #80, 각본 시험 설계 `2026-10-15-script-test-design.md`

## 1. 목적

가이드라인의 주 용도는 **카메라 구도 확인**이다. 정상일 때는 아무 알림이 없고, 카메라가 이상할 때만 팝업으로 알려 준다.
- 자리 이탈과 카메라 문제를 구분해야 팝업이 의미가 있다. 사람이 자리를 떠난 것은 팝업 대상이 아니다.
- 공부 시간 타이머를 가이드라인으로 멈출지는 각본 시험에서 "가이드라인 없이 / 켬"을 비교한 뒤 정한다. 이번에는 실제 공부 화면의 타이머를 바꾸지 않는다.

## 2. 트래킹 합치기

지금은 인식기가 세 개다: 얼굴(`useFaceTracking`), 팔용 Pose(`usePoseTracking`, 초당 15회), 가이드라인용 Pose(`usePoseGuide`, 0.5초마다). Pose 두 개는 같은 모델로 같은 영상을 두 번 본다.

새 훅 `src/tracking/useTracking.ts` 하나가 측정을 모두 맡는다.
- 웹캠 켜기, MediaPipe 실행 파일 한 번 불러오기, 얼굴 모델·Pose 모델 만들기.
- 반복 하나: 얼굴은 새 프레임마다, Pose는 초당 15회(`POSE_HZ`). 배경 확인은 1초마다(4절).
- 결과를 한 묶음으로 내보내고, 쓰는 곳이 필요한 것만 가져간다.
  - `face`: 고개·눈 (지금 `FaceState` 그대로) → 캐릭터 머리, 집중 판정
  - `pose.left`, `pose.right`: 팔 → 캐릭터 팔
  - `pose.found`, `pose.framed`, `pose.guidePoints`: 사람 인식 여부, 코·어깨가 화면 안인지, 코·어깨 화면 좌표 → 가이드라인
  - `guide`: 팝업을 띄울지 (5절)
- Pose가 실패해도 얼굴 트래킹은 계속 동작한다(지금 동작 유지). 이때 `framed`는 null → 판정에서 무시, 팝업 없음.
- `useFaceTracking.ts`, `usePoseTracking.ts`, `usePoseGuide.ts`는 지운다. 타입을 가져오는 곳(`SeatedStudy`, `HeadTrackingTest`, `SelfView`, `TrackedCharacter`, `PoseReadout`)은 새 파일을 가리키게 고친다.
- 이 단계는 동작을 바꾸지 않는 정리라 따로 커밋한다.

홀리스틱(얼굴·몸 한 번에)은 쓰지 않는다: 모델 13.7MB(지금 9.5MB), 손 인식을 끌 수 없고 몸만 빈도를 낮출 수 없음, 고개 각도에 쓰는 얼굴 회전 정보(transformation matrix)를 주지 않음. 각본 시험에서 숙였을 때 얼굴 인식이 끊긴다고 확인되면, 숙인 얼굴을 잡는지와 FPS만 짧게 따로 시험한다. 측정이 `useTracking` 한 곳에 모여 있으므로 바꿔도 그 파일만 고친다.

## 3. "화면 안" 기준 (#80) — `poseFrame.ts`

- **visibility는 쓰지 않고 좌표만 본다.** 2026-10-13 측정에서 화면 밖 관절도 visibility 0.98~1.00이 나왔다.
- 코·양 어깨의 x가 `[EDGE_MARGIN, 1 − EDGE_MARGIN]` 안, 코 y가 `[EDGE_MARGIN, 1]` 안, 어깨 y가 `≤ SHOULDER_MAX_Y` 이면 화면 안.
  - 정상 자세에서 어깨 y가 0.90~0.93이었으므로 아래쪽은 여유가 거의 없다. 값은 6절 측정으로 정한다.
- 사람을 못 찾으면 `framed = false`, `found = false`.
- `PoseReadout`의 "보임" 숫자는 오해를 부르므로 빼고 좌표·사람 인식 여부·배경 유사도를 보여 준다.

## 4. 배경 비교 (자리 이탈 vs 카메라 돌아감)

자리를 떠나면 사람만 사라지고 배경은 그대로다. 카메라가 돌아가면 배경 전체가 바뀌거나 밀린다.

- **배경 값**: 1초마다 영상을 작은 캔버스(`BG_COLS × BG_ROWS`, 예: 8×6)에 줄여 그려 칸별 평균 밝기 숫자만 읽는다. 사람이 차지한 칸(Pose 코·어깨 주변)은 비교에서 뺀다. 그림은 남기지 않고 숫자만 메모리에 두며, 화면을 나가면 버린다.
- **기준 배경**: `framed = true`인 동안 1초마다 기준을 새로 잡는다. 사용자가 카메라를 옮긴 뒤 다시 제대로 앉으면 새 배경이 기준이 된다. 기준이 없으면(앉은 뒤 한 번도 정상인 적 없음) 배경 비교는 "모름".
- **비교**: 기준과 지금 값의 상관계수(무늬가 닮은 정도). 방 전체가 밝아지거나 카메라가 노출을 바꿔도 무늬는 그대로라 영향이 작다. `BG_SAME_SCORE` 이상이면 "배경 같음".
- **무늬가 없는 배경**: 기준 값들의 퍼짐(표준편차)이 `BG_FLAT_SPREAD`보다 작으면(흰 벽 등) 배경 비교를 믿지 않고 보조 신호(5절)를 쓴다.
- 연산: 작은 그림 하나를 1초에 한 번. 새 라이브러리 없음. 코드 맨 위에 "영상은 칸별 밝기 숫자로만 읽고 남기지 않는다"는 설명 주석을 단다.

## 5. 팝업 규칙 — `poseFrame.ts`의 순수 함수

배경 확인과 같이 1초마다 지금 상황을 아래 표로 분류한다.

| 상황 | 조건 | 분류 |
|---|---|---|
| 구도 잘림 | 사람이 잡히는데 `framed = false` | 카메라 문제 |
| 사람 없음 + 배경 바뀜 | `found = false`, 배경 비교 "다름" | 카메라 문제 |
| 사람 없음 + 배경 비교 못 믿음 | `found = false`, 기준 없음 또는 무늬 없음, **최근 `INPUT_RECENT_SECONDS`(10초) 안에 키보드·마우스 입력 있음** | 카메라 문제 (보조 신호) |
| 사람 없음 + 배경 같음 | `found = false`, 배경 "같음" | 자리 이탈 → 팝업 없음 |
| 사람 없음 + 배경 비교 못 믿음 + 입력 없음 | 위 보조 신호 조건에서 입력이 없음 | 자리 이탈로 봄 → 팝업 없음 |
| 그 외 | `framed = true` 또는 Pose 결과 없음(null) | 정상 / 모름 → 팝업 없음 |

- "카메라 문제"가 `GUIDE_ALERT_SECONDS`(10초) 넘게 이어지면 팝업을 띄우고, 정상으로 돌아오면 바로 내린다.
- 입력은 있었는지와 시각만 쓴다. 무엇을 눌렀는지는 보지 않는다.
- 순수 함수: (이전 상태, {found, framed, bgSame, bgReliable, lastInputMs}, 지금 시각) → (다음 상태, 팝업 여부, 이유). Node로 시나리오 검사.

## 6. 기준값 정하기 (측정)

`/tracking`의 `PoseReadout`(좌표, 사람 인식 여부, 배경 유사도·퍼짐)로 아래 상황 값을 찍어 표로 남기고, 정상은 걸리지 않고 비정상은 모두 걸리는 값을 고른다. 근거는 `docs/판정-기준-근거.md`에 새 절로 적는다.

- 정상 착석, 숙여서 필기, 기지개
- 카메라를 좌·우·위로 조금 / 크게 돌림, 카메라에 바짝 붙음
- 한쪽 어깨만 화면 밖 (#80 재현)
- 자리 떠나기 (배경 같음이어야 함)
- 스탠드 켜고 끄기, 뒤로 사람 지나가기, 흰 벽 앞 (배경 비교 약점)

정할 값: `EDGE_MARGIN`, `SHOULDER_MAX_Y`, `BG_COLS × BG_ROWS`, `BG_SAME_SCORE`, `BG_FLAT_SPREAD`. 측정 전에는 임시값을 쓴다.

## 7. 팝업 화면과 붙이는 곳

- `src/tracking/CameraGuideNotice.tsx`: "📷 카메라에 머리와 어깨가 보이도록 맞춰 주세요". 화면 위쪽, 공부 막대 바로 아래. 공부 시작 창보다 위에 보이게. 버튼 없이 조건이 풀리면 저절로 사라진다.
- 붙이는 곳: `SeatedStudy` (앉는 순간부터 → 공부 시작 전·공부 중 모두), `/tracking`(`HeadTrackingTest`).
- 실제 공부 화면 타이머(`StudyRunner`)는 지금처럼 가이드라인 없이 판정한다.

## 8. 타이머 쪽 변경 (비교용)

- `focusLogic`의 `OUTFRAME_SECONDS` 5 → 10. 판정(얼굴이 보일 때만 잼)은 그대로이며, `/tracking`과 각본 시험의 "가이드라인 켬" 비교에만 쓰인다.
- 실제 공부 화면에서 타이머를 멈출지는 각본 시험 결과로 정한다.
- 참고(이번에 구현 안 함): "얼굴은 놓쳤지만 몸은 자리에 있음"(`found = true`, 얼굴 없음)을 알 수 있게 되므로, 숙였을 때 자리 이탈로 잡히는 문제(#119)를 고칠 단서가 된다. 각본 시험 기록에 `pose.found`를 함께 남긴다.

## 9. 작업 순서와 확인

1. 트래킹 합치기 → lint·build, 사용자가 `/tracking`과 좌석에서 고개·눈·팔이 그대로인지 확인 → 커밋
2. 좌표 기준·배경 값 계산·`PoseReadout` 표시 (임시값) → lint·build → 사용자가 6절 측정
3. 측정값 반영 + 팝업 규칙·화면 + `OUTFRAME_SECONDS` → Node 시나리오, lint·build, 사용자가 착석 직후·공부 중 확인
4. 근거 문서 절 추가, 이전 설계 문서에 이 문서 안내 한 줄

- 브랜치: `feat/wonjun/guide-redesign` (develop에서). PR에 `Closes #80`.
- 김현에게 알릴 것: `usePoseTracking`·`useFaceTracking`이 `useTracking`으로 합쳐짐(결과 형태는 같음).

## 10. 한계

- 카메라가 완전히 돌아가고, 배경 비교를 믿을 수 없고(흰 벽), 입력도 없으면 자리 이탈로 본다. 이때도 60초 뒤 "자리 이탈 의심" 표시가 떠서 본인이 확인할 계기는 있다.
- 조명이 일부만 바뀌거나 뒤에 사람이 오래 머물면 배경이 바뀐 것으로 보일 수 있다. 측정으로 확인한다.
- 기준값 측정은 1명·1환경이다. 각본 시험 정식판 때 다른 환경에서 다시 확인한다.
