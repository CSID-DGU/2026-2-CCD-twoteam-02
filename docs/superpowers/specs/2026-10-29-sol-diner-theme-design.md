# 솔카페 다이너 테마 — 설계 (2026-10-29)

관련 Issue: #57 지점별 테마(조명, 음악, 규칙). 참고 사진: 1950년대 미국식 다이너(흑백 체크 바닥, 빨간 가죽 부스·스툴, 청록 벽, 흰 타일 카운터, 빨간 네온 테두리, 천장 팬, 벽 액자).
대상 브랜치: `develop`. DB 변경 없음. 지점 공간은 김현 담당이나 이 작업은 원준이 하기로 했다(2026-10-29, 사용자 확인).

## 1. 왜

지금 지점 두 곳은 똑같은 상자 세계다. 바닥 베이지 한 색, 회색 벽, 갈색 책상. 지점마다 다른 분위기를 주면 "어디에 가서 공부할지" 고르는 재미가 생기고, 앉아서 고개를 들었을 때 보이는 장면이 달라진다. 첫 번째로 솔카페를 다이너로 바꾼다. 별다방은 그대로 둔다.

## 2. 목표 · 하지 않는 것 · 실패로 치는 것

목표 (사용자가 고른 네 가지, 앉아서 고개를 들면 보여야 하는 것)
- **카운터**: 흰 타일 몸체, 아래쪽 흑백 체크 띠, 윗면 빨간 테두리, 앞에 빨간 스툴.
- **체크 바닥**: 흑백 타일이 바닥 전체.
- **천장 팬**: 천장이 생기고 팬이 돈다.
- **벽 액자**: 청록 벽에 흰 테두리 액자.
- 배경으로 청록 벽, 빨간 네온 띠, 따뜻한 조명.
- 전부 상자·원통과 코드로 그린 텍스처로 만든다. 외부 모델·이미지 파일 없음(사용자 결정: "해보고 이상하면 모델 바꾸자").
- 테마 값은 솔카페 JSON에 두고, 화면 코드는 읽기만 한다(팀 규칙: 지점 배치는 JSON).

하지 않는 것
- 별다방 변경. 테마가 없는 지점은 지금 모습 그대로다.
- 음악·규칙(#57의 나머지), 로비·전체 지도의 건물 모양.
- 전체 지도(`WorldMap`)·키오스크 좌석 배치도의 지점 내부 색. 지금은 SVG 고정 색(베이지 바닥·갈색 책상)이라 3D 와 어긋나지만 이번엔 두고, 나중에 테마 색을 읽게 바꾼다. (사용자 결정, 7절)
- 자리 배치·좌석 수·충돌 범위 변경. 스툴만 새 장애물로 더한다.
- 부스(소파 좌석) 형태. 책상·의자는 색만 바뀐다.

실패로 치는 것
- 2D 위에서 보기가 천장에 가려 아무것도 안 보이는 것.
- 일반 노트북에서 30FPS 아래로 떨어지는 것(성능 목표).
- 별다방이 조금이라도 달라 보이는 것.

## 3. 어떻게 보이는가

좌석 배치(바뀌지 않음): 두 줄씩 마주 보는 책상 4줄(z = -4·-3.4, 1·1.6). 앉은 사람은 ±z 방향을 본다. 남쪽(z = +8)에 출입문과 커피 바(x 3, z 6.6), 동쪽 벽에 회의실 문.

- **바닥**: 흑백 체크. 한 칸 0.5m(16m 폭이면 32칸). 코드로 그린 캔버스 텍스처(512px, 8×8칸)를 `RepeatWrapping`으로 4번 반복.
- **벽**: 청록 `#1fb6b3`. 높이 2.5 그대로. 천장과 만나는 위쪽에 빨간 네온 띠(얇은 상자, 발광 재질 `emissive`) 한 줄. 후처리(bloom)는 쓰지 않으므로 실제로 번지는 빛이 아니라 **그림자 없는 밝은 빨간 띠**다. 번지는 빛을 원하면 후처리 라이브러리가 필요해 팀 승인 뒤 따로 한다. (내 판단)
- **천장**: 벽 높이 2.5에 평면 하나, 크림색 `#f3efe6`. **아래를 향한 한 면만 그린다**(`side: FrontSide`로 아래를 보게 회전). 그래서 위에서 내려다보는 2D 카메라에서는 보이지 않고 1인칭·좌석에서만 보인다.
- **천장 팬**: 6개(x -3·3 × z -6·-1.2·4.5). 모든 자리에서 고개를 들면 앞쪽에 팬이 하나는 보이도록 책상 묶음 앞뒤 통로마다 둔다(z -4 줄은 +z 를 보고, -3.4 줄은 -z 를 보는 식이라 한 줄에만 두면 절반은 등 뒤가 된다). (내 판단) 축 원통(반지름 0.06, 높이 0.3) + 날개 상자 4개(길이 0.7, 폭 0.14, 두께 0.03) 를 `useFrame`으로 초당 1.5바퀴 돌린다. 위에서 봐도 보여서 2D에서도 도는 게 보인다(괜찮음).
- **액자**: 북쪽 벽(z -8) 3개, 남쪽 벽(z 8) 2개(출입문·바 피해서), y 1.6. 흰 테두리 상자(0.9×0.7×0.04) 위에 안쪽 판(0.78×0.58)을 0.005 띄워 붙인다. 안쪽은 `patternTexture.ts`의 `posterTexture(text, bg)`(안판 비율 0.78:0.58 에 맞춘 캔버스, 둥근 모서리 없음)로 글자 포스터("DINER", "COFFEE", "ROCK'N ROLL", "OPEN 24H", "SOL")를 색 배경에 그린다. `labelTexture`는 256×96 비율이라 그대로 붙이면 글자가 세로로 늘어나서 쓰지 않는다. 벽 안쪽으로 0.11 들어온 위치(벽 두께 0.2의 절반 + 0.01).
- **카운터**(커피 바 자리 그대로, x 3 z 6.6, 3×0.8, 높이 1.0): 몸체는 흰 타일 캔버스 텍스처(타일 8칸, 회색 줄눈), 몸체 아래 0.3 높이는 체크 띠(바닥과 같은 텍스처), 윗면은 빨간 상판(3.1×0.08×0.9, `#d9353a`)과 그 가장자리 네온. "커피 바" 표지판은 그대로.
- **스툴**: 카운터 북쪽(z 5.8) x 2·3·4 세 개. 다리 원통(반지름 0.04, 높이 0.55, 크롬 `#c0c4cc`) + 방석 원통(반지름 0.18, 높이 0.1, 빨강). 걸어서 지나가지 못하게 장애물(0.4×0.4)로 넣는다.
- **책상**: 빨강 `#d9353a`. **의자**: 기본색을 흰색 `#f1f1f1`으로(빨강·흰 줄무늬의 흰 쪽). 가까이 있거나 내 자리일 때 색(주황·내 자리색)은 그대로.
- **조명**: ambient 1.2 → 1.0, directional 0.8 → 0.9, 둘 다 따뜻한 색 `#fff1dc`.

## 4. 데이터: 지점 JSON의 `theme`

`BranchLayout.theme?: BranchTheme` (없으면 지금 모습). 값은 전부 솔카페 JSON에 적는다.

```json
"theme": {
  "floor": { "pattern": "checker", "colors": ["#1a1a1a", "#f4f4f4"], "cell": 0.5 },
  "wall": { "color": "#1fb6b3", "neon": "#ff2d2d" },
  "ceiling": { "color": "#f3efe6", "fans": [{ "x": -3, "z": -6 }, { "x": 3, "z": -6 }, { "x": -3, "z": -1.2 }, { "x": 3, "z": -1.2 }, { "x": -3, "z": 4.5 }, { "x": 3, "z": 4.5 }] },
  "frames": [
    { "x": -4, "z": -8, "face": "s", "text": "DINER", "bg": "#d9353a" },
    { "x": 0,  "z": -8, "face": "s", "text": "ROCK'N ROLL", "bg": "#1fb6b3" },
    { "x": 4,  "z": -8, "face": "s", "text": "OPEN 24H", "bg": "#2b2b2b" },
    { "x": -4, "z": 8,  "face": "n", "text": "COFFEE", "bg": "#5b3d22" },
    { "x": -1.5, "z": 8, "face": "n", "text": "SOL", "bg": "#d9353a" }
  ],
  "counter": { "style": "tile", "top": "#d9353a", "stools": [{ "x": 2, "z": 5.8 }, { "x": 3, "z": 5.8 }, { "x": 4, "z": 5.8 }] },
  "desk": "#d9353a",
  "chair": "#f1f1f1",
  "light": { "ambient": 1.0, "sun": 0.9, "color": "#fff1dc" }
}
```

- `face`: 액자가 어느 쪽을 보는지(`n`·`s`·`e`·`w`). 벽 좌표를 그대로 적고 코드가 벽 안쪽으로 조금 띄운다.
- 모든 항목이 선택이다. `theme`가 있어도 `ceiling`이 없으면 천장을 안 그리는 식.

## 5. 코드 구조

```
src/space/theme.ts          순수: BranchTheme 타입, 기본값(테마 없을 때의 지금 색), framePose(face → 위치·회전), stoolBoxes(스툴 → 장애물)
src/space/patternTexture.ts 코드로 그린 텍스처: checkerTexture(colors, cells), tileTexture(tile, grout), posterTexture(text, bg). labelTexture 처럼 캐시
src/space/Decor.tsx         테마 소품 컴포넌트: Ceiling, CeilingFan, WallFrame, Counter(+Stool), NeonStrip
src/space/branches/sol.json theme 추가
src/space/layout.ts         BranchLayout.theme, obstaclesOf 에 스툴 장애물 추가(매개변수 Branch 타입에 theme 포함). obstaclesOf 는 BranchScene 의 내 캐릭터 충돌에만 쓰여 다른 화면엔 영향 없음
src/space/BranchScene.tsx   바닥·벽·책상·의자 색·텍스처를 테마에서 읽고, <Decor> 그리기, 커피 바를 테마가 있으면 Counter 로
```

- `useFrame`은 Decor 안의 팬에서만 쓴다. BranchScene은 이미 Canvas 안이라 그대로 넣을 수 있다.
- 텍스처는 `patternTexture.ts`가 한 번 만들어 캐시한다(labelTexture 방식).
- 테마가 없는 지점은 `defaultTheme`의 색으로 지금과 똑같이 그린다. 즉 BranchScene의 하드코딩 색을 기본값으로 옮기는 것뿐이다.

## 6. 확인 방법

1. `npm run dev` → 별다방: 전과 똑같다(바닥 베이지, 회색 벽, 갈색 책상, 천장 없음).
2. 솔카페 2D 위에서 보기: 체크 바닥, 빨간 책상, 카운터, 스툴 3개, 팬 3개가 보이고 천장에 가려지지 않는다.
3. 솔카페 1인칭 걷기: 청록 벽, 천장과 팬이 돌고, 액자 5개가 벽에 붙어 있고, 네온 띠가 빛난다. 스툴에 부딪힌다.
4. 자리에 앉기(북쪽을 보는 자리와 남쪽을 보는 자리 하나씩): 고개를 들면 각각 액자 3개 / 카운터·스툴·액자 2개가 보인다.
5. 성능 표시(PerfReadout)로 FPS가 30 아래로 안 떨어진다.
6. 1인칭 미니맵: 체크 바닥이 300px 에 촘촘히 찍히는데(0.5m 칸 ≈ 9px) 화살표·캐릭터를 알아볼 수 있으면 그대로 둔다. 너무 어지러우면 미니맵에서만 바닥을 단색으로 바꾸는 것을 후속으로.
7. `npm run lint`, `npm run build` 통과. `theme.ts`의 순수 함수(framePose·stoolBoxes·기본값 합치기)는 Node 스크립트로 검사.
