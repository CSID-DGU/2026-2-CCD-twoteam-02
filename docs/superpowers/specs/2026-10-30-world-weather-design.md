# 월드 날씨: 구름과 비·눈 — 설계 (2026-10-30)

관련 Issue: #317. 앞 단계: #315 광장 월드, #316 하늘과 시간(`docs/superpowers/specs/2026-10-30-world-sky-design.md`), #321 별자리 운세(`docs/superpowers/specs/2026-10-30-constellation-fortune-design.md`).
뒤로 미룬 것: #328 뇌우 번개, #329 눈 쌓임.
대상 브랜치: `develop`. DB 변경 없음. 새 라이브러리 없음. 외부 이미지 없음. **외부 서비스 1개 추가**(Open-Meteo, 키 없음, 2절).

## 1. 왜

광장 하늘(#316) 위에 구름과 비·눈을 얹어 "지금 함께 있는" 느낌을 더한다. 처음 이슈는 날짜·시각 규칙으로 정하는 가상 날씨였지만, 눈도 보고 싶어서 **실제 서울 날씨**를 따르기로 바꿨다(사용자 결정). 목적은 서비스 분위기다.

## 2. 목표 · 하지 않는 것 · 실패로 치는 것

목표 (사용자 결정, 2026-10-30)
- **실제 서울 날씨**: Open-Meteo 시간별 예보를 브라우저가 직접 받는다. 키·서버·DB 없음. 1시간마다 다시 받는다.
- **모두 같은 날씨**: 모두 같은 시간별 값을 쓰고 서울 정각에 같이 바뀐다. 구름 자리도 시각으로 계산해 같은 시각에는 같은 자리다.
- **구름·비·눈**: 떠다니는 로우폴리 구름, 내 둘레에 떨어지는 비(빗줄기)·눈(눈송이). 비·눈이 오면 하늘·빛이 어두워진다.
- **별자리는 늘 보임**: 흐리거나 비가 와도 12별자리·이름표는 그대로 보이고 눌린다(운세 #321 유지). 흩뿌린 별만 흐려진다.
- **확인용 주소**: `?weather=rain` 등으로 날씨를 바로 고정한다.

하지 않는 것
- 뇌우 번개(#328), 눈 쌓임·땅 젖음(#329), 안개, 소리, 우산.
- 실제 바람 반영. 구름은 늘 서쪽에서 동쪽으로 흐른다.
- 지점 실내의 창밖 날씨.
- 서버·DB 변경, 새 라이브러리, experiment 브랜치.

실패로 치는 것
- 같은 시각에 두 사람이 다른 날씨를 보는 것(예보가 새로 계산된 직후 몇 분은 제외, 4절).
- 정각에 구름이 튀거나 날씨가 뚝 바뀌는 것.
- 비·눈이 올 때 일반 노트북에서 30FPS 아래.
- 비 오는 밤에 별자리가 안 보이거나 안 눌리는 것.
- Open-Meteo 를 못 불렀을 때 화면이 깨지거나 화면에 경고가 뜨는 것(맑음이어야 함).
- 미니맵에 구름·비·눈이 보이는 것.

## 3. 날씨 값

화면이 쓰는 날씨는 숫자 네 개다.

```
Weather = { cloud: 0~1 (구름 양), rain: 0~1 (비 세기), snow: 0~1 (눈 세기), dim: 0~1 (어두움) }
```

### 3.1 날씨 코드 묶기 (`weatherKind`)

| Open-Meteo 날씨 코드 | 화면 날씨 |
|---|---|
| 0, 1 | 맑음 |
| 2, 3 | 구름 |
| 45, 48 (안개) | 구름 (구름 양 최소 0.8) |
| 51~57 (이슬비), 61~67 (비), 80~82 (소나기) | 비 |
| 95, 96, 99 (뇌우) | 비 (세기 1) |
| 71~77 (눈), 85, 86 (소낙눈) | 눈 |
| 그 밖 | 맑음 |

### 3.2 세기와 어두움

- 구름 양 `cloud` = `cloud_cover`(%) / 100.
- 비·눈 세기는 시간당 강수량(`precipitation`, mm, 눈도 물로 바꾼 양)으로 정한다. 0.1mm → 0.2, 1mm → 0.5, 4mm 이상 → 1, 사이는 직선으로 잇는다. 날씨 코드가 비·눈인데 강수량이 0.1mm 미만이면 0.2(`MIN_PRECIP`).
- 비·눈이 오면 구름 양은 최소 0.8.
- 어두움 `dim` = 큰 값(0.4 × 구름 양, 비·눈이 오면 0.6 + 0.4 × 세기, 아니면 0).

기준값(강수량 단계, 최소 세기, 어두움 계수 등)은 `weatherLogic.ts` 위쪽 이름 붙인 상수로 둔다.

### 3.3 시간별 값 고르기 (`weatherAt`)

- Open-Meteo 의 시간별 강수량은 "그 시각까지 지난 1시간" 합이다. 그래서 시각 T 의 값을 T−1h ~ T 구간에 쓴다(날씨 코드·구름 양도 같은 구간으로 맞춘다).
- 구간마다 3.1·3.2절로 `Weather` 숫자 넷을 먼저 만든다. 정각 앞뒤 `BLEND_MS`(5분) 동안은 앞뒤 구간의 `Weather` 숫자를 직선으로 섞는다(날씨 코드는 섞지 않음). 정각에서는 정확히 반반이다.
- 지금 시각이 받은 범위 밖이거나 목록이 비면 맑음 `{ 0, 0, 0, 0 }`.
- 날씨는 **실제 시각(`Date.now()`)** 으로 고른다. `?time` 으로 하늘 시각만 바꿔도 날씨는 지금 실제 날씨다(예보가 앞뒤 하루뿐).

### 3.4 확인용 주소 (`parseWeatherOverride`)

`?weather=종류` 또는 `?weather=종류:세기`(세기 0 초과 1 이하). 있으면 API 를 부르지 않고 그 날씨로 고정한다. 틀린 값은 무시하고 실제 날씨를 쓴다.

| 주소 | 날씨 |
|---|---|
| `clear` | 구름 0 |
| `cloudy` | 구름 0.8 |
| `rain`, `rain:0.3` | 구름 0.9, 비 0.6(또는 준 세기) |
| `snow`, `snow:0.3` | 구름 0.9, 눈 0.6(또는 준 세기) |

어두움은 3.2절 식으로 같이 계산한다. `?time=22:00&weather=rain` 처럼 하늘 시각과 같이 쓸 수 있다.

## 4. 데이터 받기 (`src/world/useWorldWeather.ts`)

- 주소: `https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.978&hourly=weather_code,cloud_cover,precipitation&past_hours=3&forecast_hours=24&timezone=UTC&timeformat=unixtime` (`weatherUrl()`). 사용자 위치는 보내지 않는다(서울 고정 좌표).
- 응답의 `hourly.time`(유닉스 초)과 같은 길이의 배열들을 `Hour[] = { ms, code, cloud, precip }[]` 로 바꾼다(`parseForecast`). 모양이 틀리면 null.
- 받는 때
  - 처음: 광장에 들어왔을 때. 다만 **모듈 변수에 저장한 값**이 이번 시간(UTC 시 = 서울 시, 서울은 정시 단위 시차)에 받은 것이면 다시 부르지 않는다(지점에 다녀와도 그대로).
  - 그다음: 다음 정각 + 1분(`setTimeout`). 모두 같은 때 다시 받아, 예보가 새로 계산돼 사람마다 다른 판을 받았더라도 금방 맞춰진다.
  - 실패: 5분 뒤 다시 시도. 그동안은 이미 받은 앞으로의 예보를 그대로 쓴다. 받은 것이 하나도 없으면 맑음.
  - 한 번에 10초가 넘으면 그만둔다(`AbortController`). 실패는 콘솔 경고만.
- 확인용 주소가 있으면 아무것도 부르지 않는다.
- 결과는 React 상태가 아니라 ref(`{ hours, override }`)로 돌려준다. 매 프레임 읽는 값이라 받을 때마다 광장을 다시 그리지 않는다.
- 사용량: 1인당 하루 24번 안쪽. Open-Meteo 무료 한도(하루 1만 번, 비상업)와 거리가 멀다.

## 5. 매 프레임 흐름

```
WorldScene: useWorldWeather() → weatherRef ─┐
                                            ▼
WorldSky useFrame:  weather = weatherAt(...) 또는 override
                    sky = applyWeather(skyState(월드 시각), weather)   ← 6절
                    하늘·빛에 넣기, frame.current = { ...sky, ms, weather }
                                            │
             ┌──────────────────────────────┼────────────────────┐
             ▼                              ▼                    ▼
      Constellations (그대로)         Clouds (새로)       Precipitation (새로, 내 위치를 따라감)
```

`WorldSky` 는 `weatherRef` 와 내 위치 `followRef`(WorldScene 의 `pos`)를 더 받는다.

## 6. 하늘·빛 어둡게 (`applyWeather(sky, weather)`, 순수 함수)

`SkyState` 를 받아 날씨를 반영한 `WeatherSky = SkyState & { fieldStars, overcast }` 를 돌려준다. 맑음이면 `SkyState` 값이 그대로이고 `fieldStars = stars`, `overcast = 0` 이다.

| 값 | 바꾸는 식 |
|---|---|
| 방향광(해·달빛) 세기 | × (1 − 0.6 · dim) |
| 주변광 세기 | × (1 − 0.3 · dim), 색을 회청색(`0x9aa6b8`) 쪽으로 dim 만큼 섞음 |
| 흩뿌린 별 `fieldStars` (새 값) | stars × (1 − cloud) × (1 − max(rain, snow)) |
| 별자리용 `stars` | **그대로** (별자리 보이기·누르기는 이 값을 씀) |
| 달 그림 `moonShow`·`moonShade` | × (1 − 0.4 · dim) |
| 가로등·창문 빛남 `glow` | max(night, 0.5 · dim) — 비 오는 낮에도 불이 살짝 켜짐 |
| 흐림 덮개 투명도 `overcast` (새 값) | 0.6 · dim × (1 − 0.7 · night) |

**흐림 덮개**: 밤 덮개처럼 반구를 하나 더 씌운다. 색은 회색(`#8a9099`)이고 투명도는 위 `overcast`. 밤에는 남색 덮개가 있으므로 덜 씌운다.

## 7. 구름 (`cloudLayout` 순수 함수 + `src/world/Clouds.tsx`)

### 7.1 자리 (`cloudLayout(ms, cloud)`)

- 구름 40개(`CLOUD_COUNT`). 고정 씨앗(317)으로 구름마다 시작 x·z(가로세로 760m 정사각형 안), 높이 80~120m, 크기 1~1.6배, 덩어리 5개의 상대 자리·크기를 정한다.
- 흐름: x = 시작 x + `CLOUD_SPEED`(초속 3m) × (ms / 1000) 을 정사각형 폭으로 감싼다(동쪽 끝 → 서쪽 끝). 방향과 속도가 늘 같아서 시각에 대해 연속이다(정각에 튀지 않음).
- 원판: 광장 가운데에서 가로 거리 300m 부터 380m(`CLOUD_RADIUS`)까지 크기를 1 → 0 으로 줄인다. 380m 밖은 0.
- 구름 양: i 번째 구름 크기 × clamp(cloud × 40 − i, 0, 1). 구름 양이 섞이며 바뀌면 구름이 하나씩 자라거나 줄어든다(갑자기 나타나지 않음).
- 결과: 덩어리 200개의 `{ x, y, z, sx, sy, sz }`(크기 0 이면 숨김). 매 프레임 부르므로 out 배열을 받아 새로 만들지 않는다.

### 7.2 그리기

- 덩어리는 낮은 면수 구(`IcosahedronGeometry` 1단계)를 위아래로 납작하게. 200개를 `InstancedMesh` 하나로 그린다(그리기 1번).
- 재질은 빛을 받지 않는 `MeshBasicMaterial`. 위는 밝고 아래는 어둡게 정점 색을 미리 넣어 입체감을 낸다.
- 전체 색은 `cloudTint(sky, weather)`(순수 함수): 낮 흰색 → 해 고도 −2°~10° 노을 주황빛(`0xffb38a`) → 밤 어두운 남회색(`0x2a3350`), 비·눈 세기만큼 회색(낮 `0x8a9099`, 밤 `0x30353f`) 쪽으로.
- 하늘 레이어(2). 위에서 보기 카메라(높이 20m, 아래를 봄)에는 걸리지 않는다.
- 위치가 매 프레임 바뀌므로 화면 밖 판정(frustum culling)은 끈다.

## 8. 비·눈 (`src/world/Precipitation.tsx`)

- 내 위치(`followRef`)를 가운데로 한 40×25×40m 상자 안에서 떨어진다. 바닥(y=0)에 닿으면 위로 돌아간다. 처음 자리는 고정 씨앗.
- **비**: 빗줄기(선분) 최대 2,000개. 초속 12m, 길이 0.6m, 서쪽에서 동쪽으로 살짝 기울임(구름 방향과 같음). 옅은 회청색 반투명(`LineBasicMaterial`).
- **눈**: 눈송이 최대 1,500개. 초속 1m, 좌우로 살랑 흔들림(점마다 다른 위상의 사인). 둥근 점(작은 캔버스로 그린 원을 `PointsMaterial` 의 `map` 으로).
- 그리는 개수 = 최대 × 세기(`drawRange`). 세기 0 이면 숨긴다.
- 위치 계산은 매 프레임 자바스크립트 배열(`Float32Array`)에서 한다. 셰이더를 쓰지 않아 읽기 쉽고 이 개수는 부담이 적다.
- 하늘 레이어(2)라 미니맵에 안 보인다. 위에서 보기에서는 빗줄기가 끝에서 보여 점처럼 보인다(괜찮음).
- 화면 밖 판정은 끈다.

## 11. 성능

- 그리기 명령: 구름 1, 흐림 덮개 1, 비 1, 눈 1 이 늘어난다(비·눈은 하나만 보임).
- 매 프레임: 덩어리 200개 자리, 입자 최대 2,000개 위치. 30FPS 에 영향이 거의 없을 것으로 본다. 화면의 FPS 표시(`PerfReadout`)로 확인한다.
- 네트워크: 1시간에 한 번, 응답 수 KB.

## 12. 확인 방법

Node (스크래치패드 검사 스크립트, 앞 작업과 같은 방식)
- `weatherKind`: 0·1 맑음, 3 구름, 45 구름, 61·81 비, 95 비(세기 1), 73·85 눈, 그 밖 맑음
- `parseForecast`: 정상 예시 → 시간 수·값 일치. 배열 길이 다름·필드 없음·JSON 아님 → null
- `weatherAt`: 구간 한가운데는 그 구간 값, 정각 ±5분은 사이 값(정각 정확히 반반), 범위 밖·빈 목록 → 맑음, 비 코드에 강수 0 → 0.2, 4mm 이상 → 1
- `parseWeatherOverride`: `rain`, `snow:0.3`, `cloudy`, `clear` 바르게 읽음. `rain:7`, `rain:0`, `fog`, 빈 값 → 무시(null)
- `cloudLayout`: 같은 시각 같은 자리, 시간이 지나면 동쪽(+x)으로, 모든 덩어리 가로 거리 380 안(밖은 크기 0)·높이 80~120 근처, 구름 양 0 → 모두 크기 0, 1 → 40개 보임, 정각 앞뒤 1초 자리 차이가 작음(초속 3m 수준)
- `applyWeather`: 맑음이면 그대로, 비면 빛·`fieldStars` 줄고 `stars` 그대로, `glow` ≥ night
- `npm run lint`, `npm run build`

화면 (사용자, 개발 서버 `npm run dev`, 로그인 후 광장)
- `?weather=cloudy`: 구름이 서쪽 → 동쪽으로 흐르고, 해를 가리고, 건물 뒤로 숨는다
- `?weather=rain`, `?weather=rain:0.3`: 빗줄기, 하늘 회색, 가로등 살짝 켜짐. 위에서 보기(V)로 바꿔도 깨지지 않고 미니맵에 비가 없다
- `?weather=snow`: 눈송이가 흔들리며 내린다
- `?time=22:00&weather=rain`: 흩뿌린 별은 사라지고 별자리는 보이고 눌린다. 달이 구름에 가려진다
- 주소 값 없이: 개발자 도구 Network 탭에 Open-Meteo 응답(200)이 있고, 지금 서울 날씨와 비슷하다
- 비가 올 때 FPS 30 이상
- 두 브라우저에서 같은 시각에 구름 자리와 날씨가 같다
