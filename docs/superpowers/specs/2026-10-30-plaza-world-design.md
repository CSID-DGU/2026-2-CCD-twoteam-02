# 광장 월드 — 설계 (2026-10-30)

관련 Issue: #315 광장 월드 (#58 걸어서 지점에 들어가는 큰 맵을 구체화). 이어지는 일: #316 하늘과 시간, #317 날씨.
대상 브랜치: `develop` (`feat/hyun/plaza-world`). DB 변경 없음. 새 라이브러리 없음. experiment 브랜치는 바꾸지 않는다.

## 1. 왜

지금 첫 화면(로비)은 16×10m 방의 북쪽 벽에 지점 문 4개가 늘어선 구조다. 문 앞에서 E를 누르면 지점으로 넘어갈 뿐이라 "어딘가로 걸어가서 공부한다"는 느낌이 없다. 로비를 바깥 광장으로 바꾸고 지점 4개(별다방·솔카페·올리브 테라스·흑요 라운지)를 건물로 세워, 광장을 걸어 건물에 들어가게 한다.

목적은 **서비스 분위기·몰입감**이다. 사용자가 매일 들어와 걷고 싶은 공간이어야 하므로 오래 쓸 기능으로 만들고 성능 목표를 지킨다. (사용자 결정, 2026-10-30)

월드는 세 단계로 나눠 만든다. 이 문서는 1단계다.
1. **광장 월드 (#315, 이 문서)**: 땅·길·건물·분수·나무·벤치·가로등, 건물로 들어가기·나오기
2. 하늘과 시간 (#316): 현실 시각에 맞춰 해·달이 뜨고 지기, 하늘색·빛, 별, 밤 조명
3. 날씨 (#317): 구름, 가끔 오는 비 (모두 같은 가상 날씨)

## 2. 목표 · 하지 않는 것 · 실패로 치는 것

목표
- 로그인하면 광장에 선다. 가운데 분수가 있고, 네 건물이 광장을 둘러싸며 입구가 모두 광장을 본다.
- 건물 입구 앞에서 E를 누르면 지금처럼 그 지점 실내 화면으로 넘어간다. 나오면 그 건물 입구 앞 광장에 건물을 등지고 선다.
- 생김새는 지금 지점 소품·캐릭터와 같은 단순한 로우폴리다. 모두 상자·원기둥·원뿔로 코드에서 그린다(`Decor.tsx` 방식). (사용자 결정: 기능만 마크처럼, 모양은 지금 느낌)
- 배치는 JSON(`src/world/world.json`)에 두고 화면 코드는 읽기만 한다. (팀 규칙: 배치는 JSON)
- 로비에 있던 기능은 광장에서 그대로 쓴다: 다른 참여자(실시간), 캐릭터를 누르면 프로필 창, 채팅, 감정표현, 오른쪽 위 메뉴(R·F·P), 전체 지도(G), 캐릭터 숨김 모드.
- 전체 지도(G)가 광장과 같은 배치를 그린다.

하지 않는 것
- 하늘이 시간에 따라 바뀌는 것, 해·달·별(#316). 이번에는 맑은 낮 하늘색 배경과 고정된 햇빛만 둔다.
- 구름·비(#317).
- 지점 실내 변경. 실내에는 하늘·창밖 풍경을 넣지 않는다.
- 화면 전환 없이 걸어서 실내로 이어지는 것. (사용자 결정: 지금 지점 화면으로 넘어감)
- 외부 3D 모델(GLB)·이미지 파일. 마음에 안 드는 소품은 나중에 따로 바꾼다.
- 언덕·높낮이 있는 땅. 땅은 평평하다(`Player`의 걷기·충돌이 평평한 땅과 상자 장애물 기준).
- 실시간 방 이름·접속 장소 이름 변경. 내부 이름 `lobby`는 그대로 둔다(develop·experiment 사이 실시간·접속 상태가 어긋나지 않게).
- experiment 브랜치. 실험 화면은 지금 로비 그대로다.

실패로 치는 것
- 일반 노트북에서 30FPS 아래로 떨어지는 것(성능 목표).
- 건물에 들어갔다 나왔을 때 다른 건물 앞이나 엉뚱한 방향으로 서는 것.
- 위에서 보기·미니맵에서 캐릭터가 점처럼 작아 알아볼 수 없는 것.
- 로비에 있던 기능(채팅·메뉴·프로필 창·다른 참여자) 중 하나라도 광장에서 빠지는 것.

## 3. 배치

단위는 m, 위쪽(-Z)이 북쪽이다. 3D 의 위에서 보기·전체 지도와 같은 방향이다.

```
                    북 (-Z)
         🌳  🌳  [  별다방  ]  🌳  🌳
         🌳          ┃입구          🌳
 [흑요 라운지]━━━━━ 광장 ━━━━━[ 솔카페 ]
       입구        ⛲  🧍시작      입구
         🌳          ┃              🌳
         🌳  🌳 [올리브 테라스] 🌳  🌳
                    남 (+Z)
```

- **월드**: 84×84m (가운데 0,0). 가장자리에 낮은 울타리(부딪힘)와 나무 줄.
- **광장**: 가운데 28×28m 돌바닥. 바깥은 잔디.
- **분수**: 광장 가운데, 지름 5m 둥근 수반 + 가운데 기둥. 부딪힌다. 물은 색이 살짝 움직이는 정도(입자 없음).
- **건물 4개**: 크기는 지점 실내와 똑같이 16×16m(지점 JSON 의 `size`에서 읽음). 가운데가 광장 중심에서 26m 떨어진 동서남북에 놓인다. 입구 벽이 광장 쪽을 본다.
  - 북: 별다방 (입구가 남쪽을 봄), 동: 솔카페 (서쪽), 남: 올리브 테라스 (북쪽), 서: 흑요 라운지 (동쪽). 실제 배치는 `world.json`에서 바꿀 수 있다.
  - 회의실이 있는 지점(`meetingDoor`)은 실내 동쪽 벽 바깥에 회의실 크기(`MEETING_ROOM.size`)의 별관을 붙인다. 전체 지도가 지금 그리는 방식과 같다.
- **길**: 광장 가장자리에서 각 건물 입구까지 폭 4m 돌길.
- **시작 위치**: 분수 남쪽(0, 6)에서 북쪽(분수·별다방 쪽)을 본다.
- **소품**: 나무는 건물 사이·가장자리에 30개 안팎, 벤치는 광장 가장자리·길가에 8개 안팎, 가로등은 광장 모서리·길가에 12개 안팎. 정확한 자리는 `world.json`에 적는다.

### 건물 방향 표기

건물의 입구 방향은 각도가 아니라 `"facing": "south" | "north" | "east" | "west"`로 적는다. 90도 단위로만 돌리면 전체 지도(SVG)의 좌표 변환이 단순해지고, JSON 을 읽는 사람이 바로 알아본다.

방향(heading)은 지금 코드와 같이 라디안, 0이 +Z(남쪽)이다. 입구 방향 각도는 south 0, west -π/2, north π, east π/2.

## 4. `world.json` 모양

```jsonc
{
  "size": { "w": 84, "d": 84 },
  "plaza": { "w": 28, "d": 28 },
  "spawn": { "x": 0, "z": 6, "heading": 3.1416 },
  "fountain": { "x": 0, "z": 0, "r": 2.5 },
  "buildings": [
    // slug: 지점 JSON 이름(BRANCH_LAYOUTS 키), x·z: 건물 가운데, facing: 입구가 보는 쪽
    { "slug": "byeol", "x": 0, "z": -26, "facing": "south", "wall": "#e8d9c4", "roof": "#a0463c" }
    // ...
  ],
  "paths": [{ "x": 0, "z": -16, "w": 4, "d": 4 }],   // 돌길 (가운데·크기)
  "trees": [{ "x": -12, "z": -30 }],
  "benches": [{ "x": -10, "z": 14.5, "facing": "north" }],
  "lamps": [{ "x": -14, "z": -14 }]
}
```

울타리는 `size`에서 계산하므로 적지 않는다. 건물 크기·입구 위치·회의실 별관은 지점 JSON 에서 계산한다.

## 5. 들어가기 · 나오기

**들어가기**
- 각 건물 입구 바깥 1.1m 앞(지금 로비 `DOOR_GAP`과 같음)을 `Player`의 "앉는 자리"로 넘긴다. 지금 로비가 문을 다루는 방식 그대로다. 가까이 가면 `onNear`, E 를 누르면 `onSeat`이 그 건물 번호로 불린다.
- 입구 위에 지점 이름 간판(`labelTexture`), 가까이 가면 문 색이 바뀐다(지금 로비 색 그대로).
- 열린 지점은 지금처럼 DB `branches`(`is_open`)로 정한다. 안 연 지점은 회색 문, "준비 중" 안내.
- **방향 바꾸기**: 실내는 입구가 늘 남쪽 벽이다. 광장 방향 = 실내 방향 + 입구 각도. 들어갈 때 `실내 방향 = 광장 방향 - 입구 각도`로 바꿔 지금처럼 이동 상태(`passage`)의 `heading`으로 넘긴다. 예: 동쪽 건물(입구가 서쪽, -π/2)에 동쪽(π/2)을 보며 들어가면 실내에서는 π(북쪽, 안쪽)를 본다.

**나오기**
- 지점 출입문 E, "로비로" 버튼(→ "광장으로"), L 키는 지금처럼 `/`로 `{ from: slug, heading }`을 넘긴다. 지점 쪽 코드는 글자만 바뀐다.
- 광장은 `from`으로 건물을 찾아 입구 바깥 2.1m 앞(지금 `ARRIVE_GAP`)에 세우고, `광장 방향 = 실내 방향 + 입구 각도`로 돌린다. 주소로 바로 들어오면 시작 위치에 선다.

**글자 바꾸기**: 화면에 보이는 "로비"는 "광장"으로. 지점 출입문 간판·안내, "로비로" 버튼, 친구 목록의 있는 곳 이름(`placeLabel('lobby')` → "광장").

## 6. 위에서 보기 · 미니맵

- **위에서 보기(V)**: 로비는 방 전체를 한 화면에 맞췄다. 84m 를 맞추면 캐릭터가 점이 된다. 광장에서는 **내 캐릭터를 따라다니며 둘레 30m 를 보여 준다.** `TopDownCamera`에 따라다니기 설정(`followRef`, `span`)을 더한다. 지점·회의실의 위에서 보기는 지금 그대로(설정을 넘기지 않음).
- **미니맵**: 같은 이유로 광장에서는 월드 전체 대신 내 둘레 40m 를 보여 준다. `Minimap`에 따라다니기 설정을 더한다. 지점·회의실은 그대로. 전체는 G 지도로 본다.
- 1인칭 걷기 카메라(`WalkCamera`)와 `Player`는 고치지 않는다.

## 7. 전체 지도(G)

지금 `mapLogic.buildWorld`는 로비 문 위치로 건물 자리를 계산하고 길·나무를 자동으로 놓는다. 이제는 `world.json`의 건물 위치·입구 방향·길·나무를 그대로 지도 좌표로 쓴다(3D 광장과 지도 좌표가 같아짐).

- `MapPlace`에 90도 단위 회전(`facing`)을 넣어, 지점 안 좌표(책상·좌석·내 위치)를 지도로 옮길 때 돌린다. 지금 회의실에 쓰는 `turned`(90도)를 일반화한다.
- 로비 사각형 대신 광장(돌바닥)·분수·길을 그린다.
- 회의실 별관 위치는 지금 계산 방식 그대로, 건물과 같이 돌린다.

## 9. 성능

- 모두 움직이지 않는 단순한 도형이고 그림자는 지금처럼 끈다.
- 같은 모양이 여러 개인 나무·가로등·벤치는 인스턴싱(drei `Instances`, 한 번의 그리기로 여러 개를 그림)으로 그린다.
- 재질은 종류별로 하나씩 만들어 같이 쓴다.
- 분수 물은 `useFrame`으로 색만 조금 바꾼다.
- 지점 화면의 FPS 표시(`PerfReadout`)를 광장에도 띄워 잰다. 기준: 일반 노트북에서 1인칭으로 광장을 걸을 때 30FPS 이상.

## 10. 문제가 생겼을 때

- `world.json`의 `slug`가 지점 JSON(`BRANCH_LAYOUTS`)에 없으면 그 건물은 그리지 않고 콘솔에 경고를 남긴다(입장 자리도 만들지 않음).
- 지점 목록(DB)을 못 읽으면 지금처럼 안내 문구를 띄운다.
- 지점에서 나올 때 `from`이 광장에 없는 건물이면 시작 위치에 선다.

## 11. 확인 방법

테스트 도구가 없으므로 순수 함수는 Node 로 검사하고(지금 `focusLogic` 등과 같은 방식), 화면은 개발 서버에서 직접 본다.

`worldLogic.ts` (Node)
- 네 방향 모두 광장 방향 → 실내 방향 → 광장 방향으로 되돌리면 원래 값이다.
- 입구 앞 자리가 건물 바깥, 광장 쪽에 있다.
- 시작 위치·입구 앞 자리·나왔을 때 설 자리가 어떤 장애물 안에도 있지 않다.
- 건물·별관끼리, 건물과 분수가 겹치지 않는다.
- 동쪽 건물에 동쪽을 보며 들어가면 실내 방향이 π(북쪽)다.

개발 서버 (`npm run dev`)
- 로그인하면 광장 시작 위치에 선다.
- 네 건물에 각각 들어갔다 나와서 그 건물 입구 앞에 건물을 등지고 선다.
- 들어갈 때 실내에서 안쪽을 보고 선다.
- 위에서 보기(V)·미니맵이 나를 따라오고 캐릭터를 알아볼 수 있다.
- G 지도가 광장과 같은 배치다.
- 두 계정이 광장에서 서로 보이고, 채팅·프로필 창·메뉴가 된다.
- FPS 표시 30 이상.
